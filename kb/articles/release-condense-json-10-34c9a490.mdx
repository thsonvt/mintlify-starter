## Full Article

I'm trying to get braver at releasing 1.0 versions. This little library is a year and a half old now - I've applied some sensible and non-disruptive fixes and shipped the big 1.0 for it. Here's an example of what it can do, lifted from the README: &#123; "foo": &#123; "bar": &#123; "string": "This is a string with foxes in it", "nested": &#123; "more": ["Here is a string", "another with foxes in it too"] &#125; &#125; &#125; &#125; Combine that with a replacements object: &#123;"1": "with foxes in it"&#125; And condense_json(input_json, replacements) produces the following: &#123; "foo": &#123; "bar": &#123; "string": &#123;"$r": ["This is a string ", &#123;"$": "1"&#125;]&#125;, "nested": &#123; "more": ["Here is a string", &#123;"$r": ["another ", &#123;"$": "1"&#125;, " too"]&#125;] &#125; &#125; &#125; &#125; It scans for strings or substrings that are present in that replacements object and replaces those with a special &#123;"$r": ...&#125; syntax in the output. You can reverse the effect with uncondense_json(condensed, replacements). The idea is to make it easier to store JSON that includes duplicated data from other related structures. I use it to save space in the SQLite logs generated by LLM - see PR #1586 for the latest iteration of that.
